# 低资源模式与提交信息插件

本 fork 保留 OpenIDEA 的编辑、Git、文件名检索和全文搜索，新增按需生成提交信息的插件，并扩展了省电模式。

## 低资源模式

在 **File → Power Save Mode（省电模式）** 开启。为保留上游默认行为，首次安装仍需手动开启；显式保存的用户设置继续生效。

开启后：

- 项目索引只记录文件名，不读取、哈希和解析每个源文件，也不载入完整符号缓存。
- 语言服务器停止；关闭模式后，为打开的文件恢复语言服务器与完整索引。完整符号缓存保留，未变化文件可复用。
- Kotlin 的自动 Maven 桥接暂停，已排队的任务会取消。
- 自动检查远端提交暂停；手动 fetch、提交和推送仍可使用。窗口隐藏时也暂停自动检查。
- 编辑器原有的自动补全、悬停文档、引用高亮等省电限制继续生效。

语言服务器和项目符号搜索在此模式下不可用；文件编辑、Git、按文件名检索和全文搜索仍可用。第三方插件有各自的任务调度，例如 Git Toolbox 的自动 fetch，需要在插件设置中单独关闭。

另外，数据库空闲回收器只在确实存在启用自动断开的连接时启动定时器；没有数据库连接时不再每五秒唤醒一次。

## 提交信息插件

插件目录：`plugins/official/commit-assistant`，ID 为 `finalpi.commit-assistant`。仓库包含编译好的 `dist/plugin.wasm`，没有后台轮询，也不会自动启动本地模型。

1. 使用本 fork 编译的桌面版，在 Settings → Plugins → Install Plugin from Disk 选择插件目录。也可使用 `openidea-plugin link` 链接该目录。
2. 在插件设置中填写 **API base URL** 和 **Model**，在 **API Key** 密钥字段中保存 Key。地址支持带或不带 `/v1` 的 OpenAI 兼容接口。
3. AI 功能需要用户授予插件网络与密钥权限。为支持自定义域名，新增了显式的 `net:*` 权限；它不会自动授予，也不改变其他插件已有的域名限制。
4. 先把准备提交的改动加入暂存区，再点击提交信息栏的生成按钮，选择 AI 或离线生成。它依据的是暂存区，不是 Changes 里的包含复选框；生成后如重新暂存，请重新生成。
5. 结果仅填入可编辑草稿，不执行暂存、提交或推送。生成期间编辑草稿或切换仓库时，旧结果会丢弃。动作搜索里的独立插件命令会复制结果到剪贴板，需要剪贴板权限。

AI 请求只在点击时执行，最多 80 个非敏感路径、24,000 字符的 diff 上下文，输出上限 512 tokens，网络超时 30 秒。常见的 `.env`、私钥、证书和含 `secret` / `credential` 的文件名会排除；这不等于完整的秘密检测，发送前仍应检查暂存区。接口默认要求 HTTPS；localhost 可使用 HTTP。

Key 由 IDE 的密钥存储管理，不写入普通配置，不放入 Git。缺少配置、网络失败、API 错误或生成期间暂存区变化时，都保留原草稿。离线模式不请求 API，只根据暂存文件名生成基础描述，适合快速填充后自行调整。

## 测量与验证

2026-11-05，在此仓库约 4,080 个文件的快照上，使用同一 Debug 构建的独立索引进程，交替运行两种模式各 3 次。每次使用新索引缓存，没有清空操作系统文件缓存；测量期间本机还在编译桌面版，因此耗时不能作为独占机器的基准。

| 中位数                 | 完整符号索引 | 仅文件名索引 |
| ---------------------- | -----------: | -----------: |
| 可检索文件             |        4,080 |        4,080 |
| 符号数                 |       61,277 |            0 |
| 工作集内存             |     45.3 MiB |     11.8 MiB |
| 私有提交内存（非 USS） |     28.4 MiB |      5.8 MiB |
| 进程累计 CPU 时间      |     17.84 秒 |      0.17 秒 |
| 完成耗时               |      8.05 秒 |      0.47 秒 |

[原始样本](performance/index-low-resource-2026-11-05.json)已随代码保存。

这些数字只反映索引进程，不包括 WebView、桌面外壳、语言服务器和其他功能，不能当作整个 IDE 的内存或空闲 CPU 降幅。用户实际项目、Release 构建和机器配置会影响结果。

Windows 可复测：

```powershell
cargo build -p ide-index --example resource_probe
./perf/compare/index-resource.ps1 -Project /absolute/path/to/project -Runs 5 -Output /absolute/path/to/report.json
```

结果包含各次原始样本。比较整个 IDE 时，应使用 Release 构建，并统计它的全部子进程；可参考上游 `perf/compare`。
